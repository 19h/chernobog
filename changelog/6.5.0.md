# Chernobog 6.5.0

Changes in [`v6.4.0...v6.5.0`](https://github.com/19h/chernobog/compare/v6.4.0...v6.5.0).
The README retains the cumulative [changes since 6.2.0](https://github.com/19h/chernobog/blob/v6.5.0/README.md).

- **CoBRA is the default MBA candidate generator** — algebraic simplification
  now uses CoBRA in builds that include it. Independent Z3 checks still prove
  the proposed value and the actual emitted microcode or ctree expression before
  replacement. `CHERNOBOG_MBA_BACKEND=legacy` selects the previous generator;
  builds with `CHERNOBOG_WITH_COBRA=OFF` retain Legacy. An exhausted or failed
  CoBRA invocation does not silently restart candidate search with Legacy.
  See [CoBRA integration and limits](https://github.com/19h/chernobog/blob/v6.5.0/docs/MBA_COBRA_SPEC.md).
- **Flag-field and mask simplification** — known-bit analysis tracks constant
  shifts, extensions, extraction, and multiplication by powers of two. It
  combines nested masks, removes masks from unobserved bits, and changes XOR
  to OR only when the possible set bits are disjoint. Plain field-store values
  can reuse eligible scalar locals without changing their destination or
  surrounding memory operations. Volatile and unresolved memory operands remain
  excluded from the ordinary-memory semantic model. See the
  [mask-normalization examples](https://github.com/19h/chernobog/blob/v6.5.0/docs/MBA_SMT.md).
- **More complete caller and loop constants** — the calls-stage pass can prove
  contextual constants after Hex-Rays narrows return values, including across
  propagatable ordinary copies marked `DONT_COMB`. It preserves those original
  instructions and does not rewrite protected copies. This additional pass runs
  only for reachable CFG cycles. If a proved proposal cannot be lowered, analysis
  continues to other sites in the same immutable snapshot instead of discarding
  all remaining opportunities.
- **Complete-word reconstruction and reusable proofs** — both generators try
  complete unmasked linear word regions up to 32 bits before their prefixes,
  including beneath typed truncations and extensions. Universally proved word
  identities are reused within the same solver session for caller, candidate,
  and emitted-value queries. A bounded proof-only normalization gives equivalent
  complemented words a common arithmetic form. Candidates retain their original
  typed semantics and still require both value proofs.
- **Legacy masked-selector reduction** — fixed conjunctive and disjunctive
  constant-mask selectors can reduce to masked XOR expressions before general
  reconstruction. Complementary masks can reduce to one XOR; partial masks retain
  their fixed output bits. Each template is proved before substitution, with
  signed promotions and narrow return conversions preserved.
- **Analysis time reserved for final scalar recovery** — validated unconditional
  chains execute directly through their assignments and stores, avoiding invariant
  inference where there is no branch or cycle. Qualifying Legacy functions reserve
  750 ms of the normal allowance for ctree recovery; masked Legacy sites retain
  their 250 ms cap. The shared per-function allowances remain 1 s for normal
  analysis and 30 s for Deep, with individual solver queries capped at 250 ms.
  These allowances do not bound total decompiler runtime. See the
  [backend scheduling and budget details](https://github.com/19h/chernobog/blob/v6.5.0/docs/MBA_COBRA_VALIDATION.md).
- **Proofs bound to the actual replacement** — emitted-object receipts retain
  the exact SDK expression that was independently checked. Before applying a
  replacement, the plugin rechecks its source, destination, types, frame, effects,
  and current analysis domain. Post-proof edits, stale snapshots, cancellation,
  and ineligible deadlines reject the replacement; CoBRA proposals cannot use
  the existing preverified Legacy fallback's deadline exception. Structural
  cleanup also advances the mutation epoch so earlier receipts cannot authorize
  later edits.
- **Backend and rejection diagnostics** — `chernobog_mba_smt_stats(ea)` reports
  the selected backend, candidate and emitted-proof outcomes, application and
  rejection counts, phase timings, and deadline overshoot. Invalid backend
  overrides and explicitly requested unavailable CoBRA builds have distinct
  diagnostics. Proof counters describe attempts; `applied` records actual
  rewrites.
